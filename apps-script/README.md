# 청년부 회계 메일 발송 Apps Script

Google Sheets의 `메일발송` 탭에서 선택한 행을 기준으로 다음 작업을 수행합니다.

- 주간/월간 보고서 기준 셀 자동 설정
- 보고서 범위를 HTML 메일 본문으로 변환
- 선택한 보고서를 PDF로 첨부
- `메일발송`, `분석` 탭을 제외한 전체 회계 파일을 XLSX로 첨부
- 테스트 발송과 실제 발송 분리
- 중복 발송 방지 및 `성공여부` 열 결과 기록
- 작업 종료 후 주간/월간 보고서의 기존 선택값 복원

## 메일발송 탭 구조

상단 1~5행에서 헤더 행을 자동으로 찾고 헤더 이름을 기준으로 열을 구분하므로 열 순서는 자유롭게 바꿀 수 있습니다. 헤더와 데이터를 **열 전체로 함께 이동**해야 합니다.

| 권장 헤더 | 내용 |
|---|---|
| 발송선택 | 발송할 행 하나를 선택하는 체크박스 |
| 보고서종류 | `주간`, `월간`, `주간+월간` |
| 발송일 | 보고서 기준일 |
| 발송메일 | 실행 계정 확인 및 답장받을 주소 |
| 수신자1~5 | 실제 수신자 |
| 참조1~5 | 참조 수신자 |
| 메일제목 | 발송 시점에 읽는 제목 |
| 메일본문 | 발송 시점에 읽는 본문 |
| 성공여부 | 처리 중·성공·실패 결과 |

`수신자`, `수신자1`, `수신자2`처럼 `수신자`로 시작하는 열을 여러 개 사용할 수 있습니다. 참조도 `참조`, `참조1`, `참조2`처럼 추가할 수 있습니다. 현재처럼 헤더가 1행이면 데이터는 2행부터 시작하며, 헤더 위에 안내 행을 추가해도 데이터 시작 행은 자동으로 계산됩니다.

본문과 제목에서 사용할 수 있는 치환자는 다음과 같습니다.

- `{발송일}` → `2026년 8월 30일`
- `{발송일ISO}` → `2026-08-30`
- `{연도}` → `2026`
- `{월}` → `8`
- `{주차}` → `5주차`
- `{주간보고}` 또는 `{주간보고 캡쳐 이미지}` → 주간보고 HTML 표
- `{월간보고}` 또는 `{월간보고 캡쳐 이미지}` → 월간보고 HTML 표

다른 사용자에게 공유할 상세 작성법과 예시는 [`MAIL_TEMPLATE_GUIDE.md`](./MAIL_TEMPLATE_GUIDE.md)를 참고합니다. 시트 상단의 `📧 회계보고 > 메일 제목/본문 작성 안내`에서도 핵심 내용을 볼 수 있습니다.

## 설치 순서

1. 원본 Google Sheets를 발송에 사용할 Google 계정으로 엽니다.
2. `확장 프로그램 > Apps Script`를 선택합니다.
3. 기본 `Code.gs` 내용을 모두 지운 뒤 이 폴더의 `Code.gs` 내용을 붙여 넣습니다.
4. Apps Script 편집기 왼쪽의 `프로젝트 설정`에서 **편집기에 appsscript.json 매니페스트 파일 표시**를 켭니다.
5. `appsscript.json`을 열고 이 폴더의 동일 파일 내용으로 교체합니다.
6. 두 파일을 저장합니다.
7. 함수 선택 목록에서 `authorizeReportAutomation`을 선택하고 **실행**합니다.
8. Google 권한 요청 화면에서 현재 스프레드시트·Drive·외부 서비스 연결·메일 발송 권한을 **모두** 승인합니다.
   - 실행 완료 여부는 Apps Script 편집기의 실행 로그에서 확인합니다.
   - 스프레드시트 탭이 열려 있다면 우측 하단에도 잠시 완료 알림이 표시됩니다.
9. 함수 선택 목록에서 `setupReportAutomation`을 선택하고 **실행**합니다.
10. 시트로 돌아와 새로고침합니다.
11. `메일발송` 탭에 `보고서종류`, `발송선택`, `성공여부` 헤더와 체크박스가 준비됐는지 확인합니다.

권한 승인 과정에서 앱 확인 경고가 표시될 수 있습니다. 본인이 만든 비공개 스크립트인지 프로젝트 이름과 계정을 확인한 후에만 승인합니다.

권한 화면에서 일부 항목만 선택하면 PDF/XLSX 생성 시 `UrlFetchApp.fetch` 권한 오류가 발생할 수 있습니다. 이 경우 Apps Script 편집기에서 `authorizeReportAutomation`을 다시 실행하고 **외부 서비스에 연결** 권한을 포함해 모든 요청 항목을 승인합니다.

## 버튼 연결

버튼이 없어도 상단 `📧 회계보고` 메뉴에서 모든 기능을 실행할 수 있습니다.

시트 안에 버튼을 추가하려면 다음과 같이 설정합니다.

1. `메일발송` 탭에서 `삽입 > 그림`을 선택합니다.
2. 1행의 원하는 위치에 **테스트 발송** 버튼을 배치합니다.
3. 버튼 우측 상단 메뉴에서 `스크립트 할당`을 선택하고 `sendTestReport`를 입력합니다.
4. 1행의 원하는 위치에 **실제 발송** 버튼을 배치합니다.
5. 스크립트 할당에 `sendSelectedReport`를 입력합니다.

함수 이름에는 괄호를 붙이지 않습니다. 그림 버튼은 PC 웹 브라우저에서만 동작하므로 모바일에서는 상단 메뉴를 사용합니다.

## 최초 테스트

1. `메일발송` 탭 3행의 발송 정보와 제목·본문을 확인합니다.
2. `발송메일`과 현재 로그인한 Google 계정 이메일이 같은지 확인합니다.
3. `보고서종류`에서 `주간`을 선택합니다.
4. `발송선택` 체크박스를 선택합니다.
5. `테스트 발송`을 실행합니다.
6. 테스트 메일은 `발송메일` 주소에만 발송됩니다. 실제 수신자와 참조 주소는 사용하지 않습니다.
7. 다음 항목을 확인합니다.
   - 제목/본문의 날짜 치환
   - HTML 보고서 표
   - 주간보고 PDF
   - `메일발송`, `분석` 탭이 빠진 XLSX
   - `성공여부` 열의 `테스트 성공` 기록
8. 문제가 없으면 같은 행의 `발송선택`을 체크한 상태에서 `실제 발송`을 실행합니다.
9. 실제 성공 후에는 체크가 자동으로 해제되고 `성공여부`에 `실제 성공`이 기록됩니다.

## 열 순서 변경

최신 코드는 상단 1~5행에서 헤더를 자동 감지한 뒤 헤더 이름으로 열을 찾습니다. 코드 교체 후에는 다음과 같은 순서를 권장합니다.

1. `발송선택`
2. `보고서종류`
3. `발송일`
4. `발송메일`
5. `수신자1`~`수신자5`
6. `참조1`~`참조5`
7. `메일제목`
8. `메일본문`
9. `성공여부`

Google Sheets에서 열 문자 머리글을 선택한 뒤 **열 전체를 이동**합니다. 헤더 셀만 잘라 붙이면 기존 행의 데이터가 다른 의미로 해석될 수 있으므로 금지합니다. 이동 후 `초기 설정`을 한 번 실행하면 현재 위치의 `보고서종류`와 `발송선택`에 데이터 검증과 체크박스가 다시 적용됩니다.

## 보고서 범위 조정

초기 설정 시 다음 이름 범위가 생성됩니다.

- `MAIL_WEEKLY_REPORT`: 기본 `주간보고서!A1:H115`
- `MAIL_MONTHLY_REPORT`: 기본 `월간보고서!A1:H70`

PDF나 HTML에 포함되는 영역을 바꾸려면 Google Sheets의 `데이터 > 이름이 지정된 범위`에서 이 두 범위만 조정하면 됩니다. 스크립트의 코드는 바꿀 필요가 없습니다.

## 보안 및 운영 주의사항

- 실제 발송 전 `링크가 있는 모든 사용자` 공유를 해제합니다.
- 스크립트 버튼은 편집자만 실행할 수 있도록 시트 편집 권한을 제한합니다.
- `발송메일` 주소와 실행 계정이 다르면 발송을 차단합니다.
- 전체 XLSX를 만들 때 임시 Drive 사본을 생성하지만, 내보내기 후 즉시 휴지통으로 이동합니다.
- `메일발송` 탭은 XLSX에서 제외되어 수신자 이메일 목록이 첨부파일에 포함되지 않습니다.
- 실제 성공한 행은 다시 발송하지 않습니다. 재발송이 필요하면 새 행을 작성합니다.

## 권한 오류 해결

`UrlFetchApp.fetch을(를) 호출할 수 있는 권한이 없습니다` 오류가 발생하면 다음 순서로 처리합니다.

1. `appsscript.json`의 `oauthScopes`에 아래 값이 정확히 있는지 확인하고 저장합니다.
   - `https://www.googleapis.com/auth/script.external_request`
2. Apps Script 편집기 함수 목록에서 `authorizeReportAutomation`을 선택해 실행합니다.
3. 권한 검토 화면에서 **외부 서비스에 연결**을 포함한 모든 항목을 승인합니다.
4. 권한 확인 완료 메시지가 표시되면 시트로 돌아가 테스트 발송을 다시 실행합니다.
5. 권한 화면이 다시 나타나지 않으면 Google 계정의 타사 앱 연결에서 이 Apps Script 프로젝트의 기존 권한을 삭제한 뒤 2번부터 다시 진행합니다.

## 원본 시트로 API 연결을 바꿀 때

1. Vercel 환경변수 `SPREADSHEET_ID`를 원본 시트 ID로 변경합니다.
2. Google 서비스 계정 이메일을 원본 시트의 뷰어로 공유합니다.
3. `api/finance/summary.py`의 인원정보 시트명을 `인원정보`로 변경하거나 환경변수화합니다.
4. 원본을 비공개로 되돌린 뒤 웹 조회 기능을 확인합니다.
5. 입력 API를 다시 사용할 때에만 서비스 계정을 편집자로 승격하고, 그 전에 서버 토큰/권한 검증을 추가합니다.
